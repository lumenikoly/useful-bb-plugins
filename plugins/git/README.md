# Git для BB

Git tool window по образцу IntelliJ IDEA: дерево веток слева, журнал с графом
по центру, файлы и детали коммита справа. Панель открывается через **Git**
в боковой навигации или меню вкладок правой панели треда.

## Установка

Из корня коллекции:

```sh
npm install
npm run build --workspace=bb-plugin-git
bb plugin install path:. --plugin git
```

Из Git после публикации:

```sh
bb plugin install git:https://github.com/lumenikoly/useful-bb-plugins --plugin git
```

Нужны BB 0.45+, SDK 0.6.15+, Node.js 22.18+, Git и OpenSSH на машине checkout.
Первая версия рассчитана на Linux/macOS: askpass использует Unix socket и `/bin/sh`.

## Работа

1. Выберите проект и checkout. В панели треда первым выбирается его окружение.
2. Откройте вкладку **Изменения**. Нажмите файл для diff рабочей копии или stage; доступны виды рядом и в строку.
3. Выберите файлы флажками и нажмите **Добавить в stage**. Удаление из stage
   сохраняет рабочую копию. Коммит включает **весь текущий stage**, включая
   изменения, ранее добавленные в терминале или другой IDE.
4. Введите сообщение и нажмите **Commit**. Git hooks и подпись коммитов
   выполняются штатно; GPG/pinentry остаётся системным.
5. **Fetch** получает выбранный remote. **Push** отправляет текущую ветку:
   сохраняет её целевую upstream-ветку на выбранном remote, а без upstream
   использует `git push --set-upstream <remote> HEAD`.
   **Pull** выполняет `git pull --ff-only` из текущего upstream.

## Ветки и журнал

**Журнал** открывается первым. Дерево содержит HEAD, локальные ветки, remote-ветки
по серверам и избранное. Поиск веток и звёздочки помогают с длинными списками.
Выбор ветки фильтрует журнал, **не переключая checkout**.

- **Переключиться**: `git switch`; для remote-ветки — диалог создания локальной
  ветки с tracking. Ветка, занятая другим worktree, недоступна для переключения.
- **＋** или **Новая ветка отсюда…**: создать и переключиться от выбранной ветки.
  В деталях коммита можно создать ветку от конкретного коммита.
- Меню **•••**: переименование (`git branch -m`) и безопасное удаление локальной
  ветки (`git branch -d`). Force-delete и удаление на сервере не выполняются.
- **Merge в …**: объединить выбранную ветку с текущей. Требуется чистая рабочая
  директория. При конфликте исправьте файлы в редакторе, добавьте их в stage и
  нажмите **Завершить merge**, либо **Отменить merge**.
- **Сравнить с HEAD**: файлы и diff между вершинами текущей и выбранной веток.

Граф построен по родителям коммитов. Журнал загружается порциями по 100, до 1000
коммитов; поиск по сообщению, автору и хешу действует среди загруженных коммитов.
Во время поиска линии графа скрываются, чтобы не рисовать ложные связи между
пропущенными коммитами. Выбор коммита показывает его файлы, автора и сообщение;
выбор файла открывает diff. Merge-коммит сравнивается с первым родителем.
На узкой панели инспектор перемещается вниз; кнопка слева от поиска скрывает
дерево веток, освобождая место журналу.

## Разные аккаунты проектов

В **Аккаунт и SSH** задайте имя и email. Плагин вызывает
`git config --local user.name/user.email`; глобальный конфиг не меняется.
Настройки общие для всех worktree одного репозитория. Пустое поле снимает
локальное переопределение и возвращает наследование, включая `includeIf`.

Автор коммита и SSH-аккаунт — разные настройки. Используйте обычные алиасы
в `~/.ssh/config` на **машине checkout**:

```sshconfig
Host github-work
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_work
  IdentitiesOnly yes

Host github-personal
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_personal
  IdentitiesOnly yes
```

В поле remote URL укажите `git@github-work:team/repo.git`. Другой проект может
использовать `git@github-personal:me/repo.git`. SSH-команду оставьте пустой для
наследования. Альтернатива — локальный `core.sshCommand`, например
`ssh -i ~/.ssh/id_work -o IdentitiesOnly=yes`. Это обычная команда Git:
вводите только команду, которую хотите запускать. Существующие `GIT_SSH_COMMAND`
и `GIT_SSH` в окружении имеют штатный приоритет Git.

SSH-команда применяется только к SSH URL. Если push URL начинается с `https://`,
Git запросит HTTPS credentials независимо от `core.sshCommand`.

URL изменяет fetch URL через `git remote set-url`. Отдельный push URL
показывается и сохраняется; изменяйте его через
`git remote set-url --push <remote> <url>`.

## Пароли и SSH

Команды исполняются на enrolled host выбранного checkout. Используются его
`~/.ssh/config`, `known_hosts`, `SSH_AUTH_SOCK` и credential helpers.
В окружение операции добавляются `GIT_ASKPASS`, `SSH_ASKPASS` и
`SSH_ASKPASS_REQUIRE=force`. Пароль, passphrase, HTTPS credentials и подтверждение
нового host key вводятся в диалоге BB. Host key автоматически не принимается.
При `BatchMode yes` OpenSSH штатно запрещает запросы пароля; отключите его
для нужного Host, если хотите интерактивный ввод.

Ответ передаётся через RPC и локальный socket, затем stdout askpass helper.
Плагин не пишет ответ в файлы, настройки или логи. Штатный credential helper
может сохранить HTTPS credentials по своим правилам. Для удалённого доступа
к BB используйте защищённое соединение.

Операции показывают вывод Git и позволяют отмену. Команды одного репозитория
сериализованы, включая worktree. Лимит операции — 10 минут, вывода команды —
4 MiB; в панели хранится хвост 256 KiB. Задания живут в памяти host worker:
при перезагрузке/отключении прерываются; перед повтором проверьте состояние Git.
Уже завершённый коммит или push отмена не откатывает.

Для сложных операций используйте стандартный терминал.

## Разработка

```sh
npm run dev:git
npm run typecheck --workspace=bb-plugin-git
npm test --workspace=bb-plugin-git
npm run build --workspace=bb-plugin-git
```

Три интеграционных теста на временных репозиториях проверяют Git workflow,
изоляцию аккаунтов, literal pathspec, rename, первый коммит, push/pull,
реальный OpenSSH askpass с зашифрованным ключом, отмену запроса пароля,
tracking-ветки, безопасное удаление, граф родителей, diff коммитов и восстановление
после merge-конфликта.
